# SlackingOffTimer 需求文档（PRD v1.0）

## 1. 文档信息
- 产品名：SlackingOffTimer（摸鱼计时器）
- 文档版本：PRD v1.0
- 产品形态：Web MVP（在线开发环境）
- 目标用户：希望低打扰记录“摸鱼时间”的上班族
- 核心定位：极简无感、一次设置、长期自动统计、每日反馈

## 2. 产品愿景与目标

### 2.1 愿景
让用户无需频繁操作，通过一次配置就能持续感知自己在工作时段的分心/摸鱼情况。

### 2.2 MVP目标
1. 完成首次工作制度配置（工作时间+休息制度）。
2. 根据当前规则自动统计摸鱼时长（Web 用活跃会话近似）。
3. 主页面清晰展示今日摸鱼时长和摸鱼占比。
4. 提供独立“最近7天趋势”页面查看阶段性变化。

## 3. 术语与口径定义
- 工作制度：工作日、上班时间、下班时间、休息时段（午休等）
- 工作窗口：满足“当天是工作日 + 当前时间在上班/下班区间内 - 休息区间”
- 摸鱼时长（fishMinutes）：工作窗口内被记录的活跃会话总分钟数
- 摸鱼占比（fishRatio）：`fishMinutes / effectiveWorkMinutes * 100%`
- 有效工作时长（effectiveWorkMinutes）：`下班时间 - 上班时间 - 休息时长`

> 说明：Web 无法监听手机系统“解锁事件”，MVP用页面活跃行为近似代替。

## 4. 用户故事（User Stories）
1. 作为新用户，我首次进入应用时只看到设置页，快速完成工作制度设置。
2. 作为用户，我设置完成后，希望应用尽量“无感”运行，不打断我正常使用。
3. 作为用户，我主动打开应用时，能第一眼看到今日摸鱼时长和占比。
4. 作为用户，我可以进入一个独立页面，查看最近7天摸鱼趋势变化。
5. 作为用户，我随时可以修改工作制度设置。

## 5. 功能需求（MVP）

### F1 首次设置流程（Onboarding）
#### 需求描述
首次打开应用，仅展示“工作制度设置页面”。

#### 输入项
- 工作日（默认周一~周五）
- 上班时间（必填）
- 下班时间（必填）
- 休息开始（可选）
- 休息结束（可选）

#### 校验规则
- 上班时间 < 下班时间
- 若填写休息时间，则休息开始 < 休息结束
- 休息区间必须落在工作时间内（MVP建议约束）

#### 输出结果
- 保存到本地存储
- 标记 onboarding 完成（如 `configured = true`）
- 页面切换到主页面

### F2 设置完成后“自动退后台”
#### 需求描述
用户保存设置后，应用应“自动退后台启动”。

#### Web实现说明（降级）
- Web无法真正系统级后台常驻，采用可用降级：
  1. 保存成功提示：“已生效，可返回桌面，系统将按规则记录会话”
  2. 若运行环境支持，尝试最小化/关闭窗口（非强依赖）
  3. 失败时保持提示即可，不阻塞流程

### F3 主页面（主动打开后默认看到）
#### 需求描述
非首次用户打开应用默认进入主页面，仅展示核心信息。

#### 展示内容
- 今日摸鱼时长（小时/分钟格式）
- 今日摸鱼占比（百分比）
- 当前状态（计时中/待机/非工作时段）
- 入口按钮：
  - 查看最近7天趋势
  - 修改工作制度

### F4 最近7天趋势页面（独立页面）
#### 需求描述
提供单独页面展示过去7天摸鱼数据，不与主页面混排。

#### 展示内容
- 每日摸鱼时长
- 每日摸鱼占比
- 7天总计/平均值（可选）
- 返回主页面入口

### F5 工作制度管理
#### 需求描述
用户可在主页面进入设置页，修改工作制度并立即生效。

#### 生效规则
- 新规则保存后，后续会话按新规则计算
- 历史数据不回算（MVP）

### F6 统计逻辑（MVP）
#### 触发规则（Web近似）
- 页面聚焦并在工作窗口内：开始/继续计时
- 页面失焦、离开工作窗口：停止计时并结算会话

#### 结算规则
- 会话分钟数按最小1分钟计（可配置）
- 仅累计到当天数据
- 跨天会话在00:00切分（建议实现）

## 6. 页面与导航结构
1. `/`（首页）
   - 若未配置：Onboarding 设置页面
   - 若已配置：今日总览页面（摸鱼时长+占比）
2. `/settings`（可选独立）
   - 修改工作制度
3. `/trends`
   - 最近7天趋势

## 7. 数据模型（建议）
```ts
type WorkSchedule = {
  workDays: number[];
  startTime: string;
  endTime: string;
  restStart?: string;
  restEnd?: string;
};

type DailyStat = {
  date: string;
  fishMinutes: number;
  effectiveWorkMinutes: number;
};

type AppConfig = {
  configured: boolean;
  schedule: WorkSchedule;
};
```

## 8. 非功能需求
- 易用性：首次设置 <= 1 分钟
- 性能：页面操作流畅，无明显卡顿
- 可维护性：UI、统计逻辑、存储分层
- 隐私：仅存储时长与时间配置，不采集内容数据

## 9. 异常与边界场景
1. 未设置制度时，不允许进入主页面统计态
2. 时间配置非法时禁止保存并提示
3. localStorage损坏时回退默认值并提示重新配置
4. 跨天时正确切分当天统计
5. 非工作日显示“非工作时段”，不累计摸鱼时长

## 10. 埋点（可选但建议）
- `onboarding_started`
- `onboarding_completed`
- `schedule_updated`
- `session_started`
- `session_stopped`
- `trends_viewed`

## 11. 验收标准（UAT）
1. 首次打开仅显示设置页
2. 设置完成后出现后台运行引导并进入非首次状态
3. 再次打开默认进入主页面（摸鱼时长 + 占比）
4. 可进入独立7天趋势页并查看数据
5. 修改工作制度后立即生效

## 12. 里程碑建议
- M1（1~2天）：Onboarding分流 + 设置存储
- M2（1~2天）：主页面指标与状态
- M3（1天）：独立趋势页
- M4（1天）：退后台降级交互 + 文档更新 + 自测
